# Internet Binder 2.2.4

Everything in 2.2.3, plus the fixes from the 2.2.3 code audit.

## Everywhere (shared code)

- **Workouts stay workouts.** One rule (`recipeOrWorkout` in kinds.js) decides "recipe or workout" for a
  caption, used by a save, an Instagram import and an old backup. Before, an old backup turned a
  numbered workout ("1. Hip circles 2x10 …") into a recipe.
- **A write that fails halfway leaves nothing behind** on Chrome and Safari (the IndexedDB transaction
  is cancelled).
- **Restores keep each save's last edit time** instead of marking everything "Changed" today.
- **The AI change log** keeps each entry as its own record, so a long Run AI no longer rewrites the
  whole log after every save. The old list is split once; the newest 3,000 entries are kept.

## Chrome and Safari

- The dashboard reads the library once per change (the Trash comes from the same read), and never runs
  two reloads at once.
- Instagram import writes its saves in batches of 500 instead of one at a time.
- Find a collection ignores accents, as on iPhone ("cafe" finds "Café").
- The copy of a 1.x library left in `chrome.storage.local` is removed once it is safely in IndexedDB.

## iPhone and iPad

- The database no longer keeps a change log nobody read (the `outbox` table is dropped).
- Fix with AI never downloads a big file it would throw away (pages over 3 MB, pictures over 15 MB stop
  at the size limit).
- New tests check that the iPhone's copies of the step-ingredients rules and the Claude model list match
  the shared code.

## Repo

- Removed old screenshot rounds (`replica/m3/screens/`, `impeccable-review/` pictures) and the unused
  `ios/Prototypes/` project from the working tree; they stay in git history.

## Build

- TestFlight build 8 for iOS and Mac (CURRENT_PROJECT_VERSION 8, MARKETING_VERSION 2.2.4).
